# Notes

Decisions made during unattended builds.

## Card actions (suspend, bury, flag, mark, reset, set due date)
- One endpoint `POST /card/{id}/action` (action + arg + back). It returns JSON for `fetch` calls (study screen) and redirects with a message for plain forms (edit page).
- Study screen: a "More" menu plus Anki's keys: `-` bury card, `=` bury note, `@` suspend card, `!` suspend note, `*` mark, Ctrl+1..7 flag, Ctrl+Shift+D set due date, Ctrl+Alt+N reset. Flag and mark update in place without reloading, so you stay on the same side of the card. The other actions move on to the next card.
- Chrome keeps Ctrl+1..7 for switching tabs when the page does not have focus. The menu's flag buttons always work, which matters most on touch screens.
- Pressing the same flag again clears it, as in Anki. "Reset to new" uses `schedule_cards_as_new(restore_position=True, reset_counts=False)`, which matches Anki's dialog defaults.
- Browse is still in notes mode (cards mode comes with the Browse upgrade item), so per-card actions are in a "Cards" panel on the note's edit page, which Browse links to. Browse rows are tinted like Anki's: yellow for suspended, the flag colour for flagged, purple for marked.
- The study screen's Undo now also covers these actions. It uses the engine's own undo labels: Suspend, Bury, Set Flag, Update/Remove Tag, Reset Card, Set Due Date.
- Screenshots: Playwright's Chromium can't start on this machine because the system library libnspr4 is missing. Installing it needs sudo, which these rules forbid, so no screenshots were taken. `tests/shots_card_actions.py` will make them once the library is installed (`sudo npx playwright install-deps`). The pages were checked through the test client instead.

## Card info page
- Data comes from the engine's `col.card_stats_data(cid)` (the same call Anki's Card Info window uses), so dates, times and the review history match Anki. History is newest first, as in Anki.
- Difficulty is shown as a percentage, `(D - 1) / 9`, as Anki does. Stability is shown as a time span.
- Turning FSRS off with the Settings toggle leaves the FSRS memory state on cards. The page follows the collection's FSRS setting: stability/difficulty/retrievability when it is on, ease when it is off.
- Links: study screen "More" menu and the `I` key (Anki's reviewer shortcut); a "Card info" button per card on the edit page's Cards panel; an ⓘ link per row in Browse, which opens the note's first card because Browse is still notes-only. Each link passes `back=` so the page has a Back button. Off-site back URLs are ignored.
- Leaving the study screen for card info and returning restarts the answer timer for that card. This is acceptable for now.
- Screenshots: Chromium still can't start (libnspr4 missing, needs sudo). `tests/shots_card_info.py` will take them once it is installed.

## Browse upgrade
- Rows and cells come from the engine's browser table (`browser_row_for_id`), so the columns read exactly as in Anki's browser (dates, "3 days", "250%", notes-mode "Avg. Ease" etc.). The engine reads Anki's `BROWSER_TABLE_SHOW_NOTES_MODE` flag to decide whether an id is a card or a note, so the page keeps that flag in sync with the chosen mode. (Forgetting this made notes-mode rows vanish at random, because note ids were looked up as card ids.)
- Notes mode stays the default, as Browse was notes-only before. The chosen mode is remembered in the collection config (`flashcardsBrowseMode`). Sort column and direction use Anki's own keys (`sortType`/`sortBackwards`, `noteSortType`/`browserNoteSortBackwards`), and chosen columns use `activeCols`/`activeNoteCols`. So they match desktop Anki after a sync.
- Default columns, used until the user picks their own: sort field, card type (cards mode) or note type (notes mode), deck, due, interval, ease, reviews, lapses, plus tags in notes mode. Anki's own defaults have only four columns, and the plan asks for the scheduling ones. "Default columns" in the chooser restores these.
- Clicking a header sorts by the column's natural order (Anki's `sorting_*` value); clicking again reverses it. Columns the engine can't sort in the current mode (question, answer; FSRS columns in notes mode) aren't links.
- The State column (flag dot, ★, Suspended/Buried/…) and the ⓘ card-info link are kept in both modes. Row tints use the engine's row colour in cards mode, and the card-based summary in notes mode.
- Selection: a checkbox per row, a "select all on page" box, and "All N in this search", which applies to every match, not only the visible 100. One Action menu with its options shown for the chosen action. Delete and Reset ask first.
- Delete removes whole notes in both modes, as Anki's browser does. Reposition only touches new cards (`reposition_new_cards`). It defaults to start 0, step 1, no randomize, no shift. If none of the selected cards is new, it says so.
- Find and replace uses `col.find_and_replace` (one field or all fields) and `col.tags.find_and_replace` for the "Tags" choice. It works on the selected notes, or every note in the search when "All" is ticked. A bad regex is caught before calling the engine. The field list is every field name across note types. The engine skips notes that don't have that field.
- No undo button on Browse yet; the engine records these as undoable ops, and the "Undo/redo everywhere" plan item will expose it.
- Screenshots: Chromium still can't start (libnspr4 missing). `tests/shots_browse.py` will take them later.

## Study screen parity
- "Again": the engine's v3 queue already shows a lapsed/learning card again once it is within the learn-ahead limit (20 min by default), so a lone card comes straight back. When the only cards left are learning cards due later than that, the page now shows a "next learning card will be ready in N minutes" screen (from `congratulations_info().secs_until_next_learn`) that reloads itself, instead of saying the deck is finished. This matches Anki's congrats-screen message.
- Edit and Card info pass `back=/study/<did>?cid=…&shown=1&ms=…&typed=…`. The study page resumes the same card on the same side with the answer timer carried on, if that card is still at the top of the queue; otherwise it just shows the next card. `E` opens Edit (Anki's key). The edit page now URL-encodes `back`, so a back URL with its own query string survives the round trip (it was being cut at the first `&`). The Card info page's "Edit note" link had the same problem and is fixed too.
- Type in the answer is ported from Anki's reviewer (`typeAnsQuestionFilter`/`typeAnsAnswerFilter`): `type:Field`, `type:cloze:Field` (via `extract_cloze_for_typing`) and `type:nc:Field` (combining off). Unknown field shows Anki's warning, an empty field removes the box. The comparison HTML comes from `col.compare_answer` through `POST /study/<did>/typeans` when the answer is shown; Anki's colours (typeGood/typeBad/typeMissed) are in the card CSS. Keys typed into the box are not treated as shortcuts; Enter shows the answer.
- Audio: `[sound:]` now renders Anki's round play button instead of an `<audio>` control. The parent page holds a small queue player. Autoplay follows the deck preset's `autoplay`; on the answer side autoplay plays the answer's tags only; replay (`R`/`F5`, 🔊 button, More menu) plays the question tags on the front and, if `replayq` is on, question + answer tags on the back — the same as Anki's reviewer. TTS tags (`{{tts …}}`) use the browser's speech synthesis with the tag's language and speed. Video files are shown inline with controls and are not autoplayed.
- Browsers (Safari on iPad in particular) may block autoplay on a freshly loaded page. When that happens the page shows "Tap 🔊 to play the audio" rather than failing silently. Coming back from Edit doesn't replay the audio.
- Leech: after answering, `sched.state_is_leech(new_state)` is checked and Anki's tooltip text is shown as a toast on the next card ("Card was a leech." plus "It has been suspended." when the preset suspends leeches). If that was the last card, the notice is shown with the congratulations message on the deck overview.
- Study script values are written with a helper that escapes `<`, so card templates containing `</script>` (common in shared decks) and text from the URL can't break out of the page's script.
- Screenshots: Chromium still can't start (libnspr4 missing). `tests/shots_study.py` will take them and also fails on any page JavaScript error once it can run. The JS was reviewed by hand.

## Deck options parity
- The page (`/deck/<id>/options`) reads and saves through `get_deck_configs_for_update` / `update_deck_configs`, the calls Anki's own options screen uses, so the engine validates values, applies to subdecks (`UPDATE_DECK_CONFIGS_MODE_APPLY_TO_CHILDREN`), removes presets and updates FSRS memory states. Unknown legacy keys survive because the engine's protobuf keeps them.
- Code lives in `flashcards/deck_options.py` (an APIRouter included at the bottom of `app.py`), so app.py stays under 1500 lines. The Dockerfile now also copies `flashcards/`; without that the container would fail to start.
- The overview's quick options form is replaced by a summary line and an "Options" button. `POST /deck/<id>/options` still accepts the old three fields (`new_per_day`, `rev_per_day`, `retention`); fields a form doesn't send are left alone.
- Presets: Add starts from Anki's defaults, Clone copies the shown preset. Both take an optional name (a number is added to duplicate names) and switch the deck to the new preset straight away. Anki does this inside the dialog and saves on close; here each button is its own save. Rename does not move the deck. Delete is not offered for Default (Anki forbids it too); decks that used a deleted preset go back to Default. Choosing a preset in the list shows its values with a note that saving will switch the deck to it.
- "This deck only" new/review limits are included. "Today only" limits, auto-advance, the timer display, easy days, historical retention and custom scheduling are left out for now. Their values are kept untouched on save.
- The FSRS switch on this page is collection-wide, like Anki's, and is the same setting as the toggle on the Settings page. "Reschedule cards on change" is passed to the engine.
- FSRS parameters: a comma-separated box. If the text is unchanged, nothing is rewritten. A new list must have 17, 19 or 21 numbers (FSRS 4/5/6). It is stored in the matching field and the other fields are cleared. Blank means defaults.
- Optimize saves the form first, then calls `compute_fsrs_params` with the preset's search (or the "Optimize search" box, default `preset:"Name" -is:suspended`, as in Anki), the "ignore reviews before" date, and the number of relearning steps. If there are no reviews, it says so. If the result equals the current parameters, it says they are already the best fit. Otherwise it saves the new parameters to `fsrs_params_6`. The health check is off, and "Optimize all presets" is not included.
- SM-2-only fields sit in an "Advanced (SM-2)" section that is folded away when FSRS is on. Out-of-range numbers are clamped to Anki's limits. Bad steps, dates or numbers are rejected with a message, and nothing is saved.
- Screenshots: Chromium still can't start (libnspr4 missing). `tests/shots_deck_options.py` will take them, and it fails on page JS errors.

## Custom study
- The page (`/deck/<id>/custom`, code in `flashcards/custom_study.py`) uses the engine's `custom_study_defaults` and `custom_study`, the same calls as Anki's dialog. Labels come from the engine's translations (`col.tr.custom_study_*`), so the wording matches Anki.
- Number limits match Anki's dialog: limit changes from -99999 to 99999 (negative lowers today's limit), forgotten cards 1–30 days, review ahead / preview 1–99999 days, 100 cards by default for "study by card state or tag". Out-of-range numbers are clamped. Starting values for the limit changes come from the engine (`extend_new`/`extend_review`), which is 0 on a fresh collection.
- Anki opens a separate tag chooser after OK. Here the include/exclude tag checkboxes sit in the same form, ticked as the engine remembers from last time. Ticking no "include" tag means any tag. The card-state list defaults to "New cards only", the first entry of Anki's list.
- Raising a limit stays on the deck's overview. The other choices build (or rebuild) the "Custom Study Session" filtered deck; the engine selects it, and its overview is shown, as in Anki. If nothing matches, the engine's message ("No cards matched…") is shown and the form stays on the same choice, as Anki keeps its dialog open. An existing normal deck called "Custom Study Session" gives the engine's "Please rename…" message.
- Like Anki, a deck with no cards only allows the two limit options. Custom study is not offered on filtered decks.
- Filtered deck overviews now have Rebuild and Empty buttons (`rebuild_filtered_deck` / `empty_filtered_deck`), since custom study makes a filtered deck and there was no way to return its cards except deleting it. Creating and editing filtered decks is still the next plan item. The congratulations screen links to Custom study, as Anki's does.

## Filtered decks
- The form (`/filtered/new`, `/deck/<id>/filtered`, code in `flashcards/filtered_decks.py`) uses `get_or_create_filtered_deck` and `add_or_update_filtered_deck`, the calls behind Anki's Filtered Deck dialog. A new deck starts from the engine's defaults, which are based on the current deck ("deck:X is:due", 100, random; second filter "deck:X is:new", 20, order due). Saving rebuilds the deck, as Anki does. Labels and the order list come from the engine (`filtered_deck_order_labels`), so the wording matches Anki.
- Entry points: "Create filtered deck" on the deck list (Anki: Tools > Create Filtered Deck), a "Filtered deck" button in Browse that starts from the current search (Anki's browser has the same action), and an "Options" button on a filtered deck's overview. `?did=` picks the deck the defaults are based on.
- Rebuild/Empty routes moved from `custom_study.py` to `filtered_decks.py`. The URLs and behaviour are the same.
- Preview delays (shown when "Reschedule" is off) are entered in seconds, the unit the engine stores (`preview_again_secs` etc.). Anki's hint text says "0 = return card to original deck"; the page shows it with "seconds". Range 0–99999. Limits are clamped to 1–99999, like custom study.
- Errors keep the form open with the values entered, like Anki's dialog: no matches (the engine's message, plus a "Show any excluded cards" link to Browse with that search, in cards mode), invalid search, an empty first search ("Please select something."), non-numbers, and unknown order values. Posting a normal deck's id to the save route is refused, so a normal deck can't be turned into a filtered one.
- `tests/test_study.py` fails between 03:00 and 04:00 local time: its 60-minute learning step crosses the 04:00 day cutoff, so the engine moves the card to tomorrow and the "next learning card" screen doesn't appear. This is a timing problem in the existing test, not a bug from this change. The run waited until after 04:00 and re-ran it before committing. Worth making the test independent of the clock later.

## Note type manager
- Code in `flashcards/notetypes.py`. Everything goes through the engine: stock types from `get_stock_notetype_legacy` (via `anki.stdmodels.get_stock_notetypes`), field/card-type edits with the `col.models` helpers then `update_dict` (the engine validates templates and moves note content), the preview with `TemplateRenderContext.from_card_layout` (what Anki's card layout screen uses), and Change Note Type with `change_notetype_info` + `change_notetype_of_notes`.
- Entry points: Settings ("Manage note types", like Anki's Tools menu), a "Cards…" button on Add, and "Cards… / Fields… / Change note type" on Edit. Browse's Action menu has "Change note type", which opens the mapping page for the ticked notes, or for the whole search when "All" is ticked (passed as the search so the URL stays short). The nav bar was not changed.
- Add offers "Add: <stock type>" and "Clone: <existing>", like Anki's Add Note Type dialog. A blank name keeps the type's name, and duplicate names get the engine's unique suffix (`ensure_name_unique`), also on rename. The last note type can't be deleted.
- Field names follow Anki's rules from aqt/fields.py: `: { } "` are removed, leading `# / ^` are stripped, and names must be unique (case-insensitive). The last field can't be deleted. Field options cover font, size, description, sort field, RTL, sticky, HTML editor by default, collapsed and exclude from search. Most of these only matter once the rich editor item uses them.
- Each action saves straight away (Anki saves when its dialog closes). The engine refuses two card types with identical fronts, so "Add card type" copies the current card type (as Anki does) and adds an HTML comment `<!-- Card N: edit this front -->` to its front. The comment doesn't show on cards. Cloze types can't get more card types, as in Anki.
- The template editor saves front, back and the shared CSS together. If the engine rejects a template, the page stays open with the typed text and the engine's message, and nothing is saved. Unsaved edits trigger the browser's "leave page?" prompt. Ctrl/Cmd+S saves, and Tab inserts spaces in the code boxes.
- Preview: uses the note from `?nid=` (Edit's "Cards…"), else the first note of the type, else a blank note showing "(Field)" placeholders, as Anki does. Cloze types get a "Cloze N" chooser. The engine takes the cloze number from the template dict's `ord`, not the card's, so it is set there. Type-in boxes show as a disabled input, and audio markers as a play icon.
- Change note type: one row per new field/card type with a "takes content from" choice (engine defaults: match by name, then position). "(Nothing)" drops it. Card mapping is hidden for changes to or from cloze, where the engine matches by cloze number. Notes of different types are refused with Anki's wording.
- Not included yet: "Restore to stock" and the field option "Prevent deletion".
- Screenshots: Chromium still can't start (libnspr4 missing), and Node isn't allowed in these runs, so the page JS was checked by hand. `tests/shots_notetypes.py` will take the screenshots, checks that the live preview updates, and fails on page JS errors.

## Rich editor (Add/Edit)
- Add and Edit moved from app.py into `flashcards/editor.py` (same URLs and form fields: `ntid`, `did`, `f0…`, `tags`, `upload`), so app.py stays well under 1500 lines. Each field is still a plain `<textarea name="fN">` (that is the HTML editor); the script puts a contenteditable box in front of it and keeps the two in step. Without JavaScript the page still works with plain textareas and the old file field.
- Formatting uses the browser's `execCommand`, like older Anki editors. Bold/italic/underline give `<b>/<i>/<u>`; colours give `<span style="color:…">` (styleWithCSS only for colours). In the HTML editor, B/I/U/sub/sup wrap the selection in tags; other buttons do nothing there except cloze, MathJax and media, which insert text.
- Cloze: the number comes from the highest `{{cN::` in all fields (+1 for a new card; the same number with Alt, 1 if none), as in Anki. On non-cloze note types the button shows Anki's message and does nothing.
- Keys follow Anki: Ctrl+Shift+C / Ctrl+Shift+Alt+C, Ctrl+M then M or E (MathJax), Ctrl+R remove formatting, Ctrl+= / Ctrl+Shift+= sub/superscript, Ctrl+Shift+X HTML editor, Ctrl+Shift+P preview, F3 attach, F7 text colour, Ctrl+Enter add/save. Cmd works in place of Ctrl. They only act while a field has focus (except Ctrl+Enter).
- MathJax: the engine leaves `\(…\)` and `\[…\]` in the card HTML; `card_doc` adds MathJax 3 (configured like Anki's reviewer: display maths only with `\[ \]`) only when a card contains them. It loads from cdn.jsdelivr.net because the `anki` package doesn't ship MathJax (desktop Anki bundles it in aqt). So MathJax needs internet access; without it the TeX source shows. The editor itself shows the TeX source, not rendered maths; use Preview. When typeset, the card frame gets an `fc-resize` event so the study screen and previews resize it.
- Media: `POST /media/upload` stores files with `col.media.write_data` (which renames on clashes) and returns `<img src="name">` for pictures and `[sound:name]` for audio and video, like Anki. Pasted pictures are named `paste-<sha1>.ext` as in Anki. Limit 100 MB. Other file types are refused.
- Pasting HTML keeps only basic formatting (b/i/u/em/strong/sub/sup/lists/tables/paragraphs/line breaks). Ctrl+Shift+V pastes plain text. Images inside pasted HTML are kept only if they have an http(s) address, and they stay remote. Anki downloads them into the media folder instead; that is not done here.
- In the rich box, `<script>`/`<style>`/iframes and `on…` attributes in a field are not shown (they would run inside the app page). The field keeps them unless you edit that field in the rich box. Editing in the HTML editor keeps everything.
- Recording uses the browser's MediaRecorder (webm on Chrome, m4a on Safari), saved as `[sound:rec-YYYYMMDD-HHMMSS.ext]`. Desktop Anki records mp3. Both formats play in desktop Anki and AnkiDroid. Browsers only allow the microphone on https or localhost; otherwise the page says so.
- Sticky: the 📌 toggles the field's `sticky` option in the note type (Anki saves it the same way). After a successful Add, pinned fields keep their content and tags are always kept, as in Anki's Add window. The kept values live in server memory per user and note type. They are lost on restart, like closing Anki's Add window. Switching note type on Add carries fields with the same name and the tags over (sessionStorage).
- Checks go through the engine's `fields_check`. While typing: a duplicate first field turns red and shows "Show Duplicates", which opens Browse with the engine-built `dupe:` search. Cloze in a non-cloze type or field shows Anki's warning. On Add, an empty first field and cloze-in-wrong-place are refused. A cloze note without clozes shows Anki's "Proceed?" question with an "Add anyway" button. Refused input is shown again instead of being lost. Duplicates can still be added, as in Anki. Edit saves without these checks, as Anki's editor does.
- Preview renders the unsaved note with `Note.ephemeral_card`. It shows one tab per card the note would make: each cloze number, or each card type except ones whose front would be blank (e.g. the optional reverse without "Add Reverse"). It updates as you type and saves nothing.
- Screenshots: Chromium still can't start (exit 127, missing libraries), and Node isn't allowed, so the JS was checked by hand. `tests/shots_editor.py` drives the editor (typing, bold, cloze keys, MathJax, duplicate warning, preview), takes the screenshots, and fails on page JS errors once a browser can run.

## Image occlusion
- Code in `flashcards/image_occlusion.py` (editor and routes) and `flashcards/io_review.py` (drawing masks on cards). Everything goes through the engine's image occlusion calls: `add_image_occlusion_notetype` (only when no IO note type exists yet), `add_image_occlusion_note`, `get_image_occlusion_note`, `update_image_occlusion_note`. The engine copies the picture into the media folder itself (reusing the file if the same picture is added again) and adds the note to the current deck, so the chosen deck is selected first.
- Masks are saved in Anki's current format: `{{cN::image-occlusion:rect:left=.1:top=.2:width=.3:height=.4:oi=1}}`. Positions are fractions of the image size, with 4 decimals and no leading zero, as Anki writes them. Every shape gets `oi=1` for "Hide all, guess one" and none for "Hide one, guess one". Shapes in one group share a cloze number. New notes are numbered 1, 2, 3… in drawing order. Edits keep existing numbers, and new shapes get the next free one, so each card's scheduling stays with the right mask, as in Anki. Removing every shape of a number leaves that card behind as an empty card, as Anki does.
- Desktop Anki's card template calls `anki.imageOcclusion.setup()`, which lives in Anki's reviewer JavaScript, not in the `anki` package. `io_review.py` is a small port. It reads the hidden `.cloze` / `.cloze-inactive` / `.cloze-highlight` divs the engine renders and paints them on the canvas with the colours from the note type's CSS (`--active-shape-color` etc.). Inactive shapes are drawn only when they have `oi`. The answer side's "Toggle Masks" button hides and shows the canvas. `card_doc` adds the port only to cards that call setup(), so it works on the study screen, in previews and on the card layout screen. Not ported: Anki's click-to-reveal and its iOS canvas size cap.
- The editor draws with an SVG over the image, using pointer events, so mouse, pen and touch all work. Tools follow Anki's: Select (S), Rectangle (R), Ellipse (E), Undo/Redo (Ctrl+Z / Ctrl+Y), Delete, Duplicate (Ctrl+D), Group (Ctrl+G), Ungroup (Ctrl+Shift+G) and Select all (Ctrl+A). Arrow keys nudge, and there is a translucency toggle. Tapping a grouped shape selects the whole group, like Anki. "+ Multi" lets touch users tap several shapes to group them, since an iPad has no Shift key. In Select mode the page can still be scrolled or pinched unless the finger starts on a shape. In the drawing modes the image area doesn't scroll. Resizing uses one corner handle. Not included: Anki's polygon and text tools, rotation handles, zoom and alignment buttons.
- Notes made in desktop Anki may contain polygons, text labels or a rotation angle. These are drawn on cards and kept when the note is edited here. Polygons and text can be moved or deleted, not reshaped. Anki draws polygon points shifted so their top-left corner sits at `left/top`. The editor converts them to plain positions and writes `left/top` back as the top-left of the points, which draws the same in both apps. Notes from Anki 23.10 stored pixel positions. If any position is above 1.5, the note is treated as pixel-based: cards scale by the image's natural size, and the editor converts to fractions once the image loads, so saving upgrades the note (newer Anki versions do the same).
- Add: the picture comes from the file chooser, drag-and-drop, Ctrl/⌘+V, or the "Paste Image from Clipboard" button. That button needs https or localhost; elsewhere it says to press Ctrl+V. Pasted pictures are named `paste-<sha1>.ext` like Anki's. The picture is uploaded only on Add, together with the masks. The page posts with fetch, so a refused add (no masks, wrong note type, filtered deck…) keeps the picture and masks on screen. Without fetch the same routes answer with a redirect and a flash message. Choosing an IO note type on the Add page (or `/add?nt=<IO type>`) opens the mask editor, as Anki's Add window switches mode. The Add page also has an "Image Occlusion" button. The IO page lists only note types the engine accepts as image occlusion types.
- Edit: `/edit/<nid>` for an IO note opens `/io/<nid>` with the same `back`, so the study screen and Browse return correctly. "Edit fields as text" (`/edit/<nid>?raw=1`) still opens the normal field editor, e.g. for the Comments field, which Anki's IO editor doesn't show either. The IO editor doesn't change the deck; use the card panel or Browse for that.
- Header and Back Extra are plain HTML boxes here, not the rich editor.
- Screenshots: Chromium still can't start (exit 127, missing libraries), and no JavaScript engine is available (Node isn't used in these runs). The editor and review scripts were checked by hand and with a bracket-balance check. `tests/shots_image_occlusion.py` drives the whole flow (pick an image, draw a rectangle and an ellipse, group, add, edit, study) and checks that the card's canvas is actually painted. It takes the screenshots and fails on page JS errors once a browser can run.

## Import / export
- Code in `flashcards/import_export.py`; the old `/import` routes moved out of app.py (same URL and form field `file`). Everything uses the engine: `import_anki_package` (+ `get_import_anki_package_presets` for the default options), `get_csv_metadata` + `import_csv`, the backend's `import_collection_package`, and `export_collection_package` / `export_anki_package` / `export_note_csv` / `export_card_csv`. Labels mostly come from the engine's translations.
- The Import page has two forms: "Import a deck" (.apkg/.colpkg/.zip, with Anki's options folded under "Options") and "Import a text file" (.csv/.tsv/.txt). Each refuses the other's file types with a pointer to the right form, so the existing test that a .txt is refused by the package form still holds. A post with no options (old form, scripts) uses the engine's saved presets.
- After an .apkg import the app goes to the deck list with a summary (as before); the per-note log (status, first two fields, Browse link) is kept in server memory and shown on the Import page as "Last import". It is lost on restart. Text imports go back to the Import page with the log.
- The engine's `first_field_match` list means updated (Update), skipped (Preserve) or added (Duplicate), depending on "Existing notes"; the summary counts it that way. Found by testing.
- Text import: the file is uploaded once and kept in the system temp folder (`flashcards-uploads/`, random name, owner checked, removed after import/cancel or after a day). Changing the separator, note type or HTML box reloads the page and asks the engine again, so its column guesses and default field mapping match Anki's. File headers (`#separator`, `#html`, `#deck`, `#notetype`, `#tags`, columns) are honoured; forced settings show "(set by the file)". A `#deck:` naming a deck that doesn't exist shows "Name (new deck)". The first field must be mapped (Anki's message). A refused import keeps the form and choices. Like Anki, a header row in a CSV without `#columns:` is imported as a note.
- .colpkg import: separate confirm page with Anki's warning, current note/card counts and a required tick box. Before replacing, the engine makes a backup of the current collection (`create_backup`, forced) in `data/users/<name>/backups/` (the folder the later backups item will use). Then the collection is closed, the engine replaces it, and a fresh Collection is opened. If the package is broken, the old collection is reopened unchanged. A missing `fsrs` setting in the imported file is saved as off, which is desktop Anki's meaning (new accounts here still default to on).
- Export page: Anki's four formats with the options each has (others hidden by JS; without JS all show and irrelevant ones are ignored). Scope: all decks, any deck, or "Selected Notes" when opened from Browse's new Export button (the current search; there is no per-row export of ticked rows). The deck overview's "Export .apkg" button now opens this page with the deck chosen; the old `/deck/<id>/export` route still works. Exporting a .colpkg makes the engine close the collection; it is reopened straight after. File names follow Anki: `collection-YYYY-MM-DD@HH-MM-SS.colpkg`, deck name `.apkg`/`.txt`, `All Decks.txt`, `Selected Notes.txt`.
- Not included: Anki's legacy importers (Mnemosyne, SuperMemo, Pauker), the "guid column" choice (kept from the file header only), and exporting media files alone.
