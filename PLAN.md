## Round 3: offline studying (like real Anki on iPad/Chromebook with no signal)
Design (keep Anki's real engine as the source of truth; the device only caches and queues):
- The app is already a Home Screen web app with a service worker (flashcards/touch.py). Extend it.
- Offline review = a downloaded snapshot + an answer queue that the server replays in order with the real engine.

- [x] Offline study, part 1 (download): per person, a "Make available offline" switch per deck (deck overview) and in Preferences (all decks). While online the browser keeps an IndexedDB copy of, for each offline deck: today's queue up to the deck limits plus up to 3 days ahead (setting), each card's rendered question/answer HTML (same as the study screen, add-on output included), its media files (Cache Storage), and the engine's four next states/interval labels (describe_next_states). Refresh it in the background on every page load and after each answer when online. Show "Offline ready · updated 2 min ago · 54 cards, 12 MB" on the deck overview. Storage use shown and a "Remove offline copy" button. Respect iPad Safari limits (ask navigator.storage.persist(), keep media under a set cap, warn if the cap is hit).
  Screenshot script written (tests/shots_offline.py) but Chromium still can't start here (missing system libraries, no sudo).
- [ ] Offline study, part 2 (studying with no connection): when the server can't be reached, the service worker serves an offline study page (deck list of offline decks, counts, the same study screen look) driven from IndexedDB. Answers are stored in an IndexedDB queue with card id, rating, time taken and the timestamp. Cards answered Again (or still in learning) are shown again later in the same offline session after their learning step, like Anki. Button labels use the downloaded states for the first answer; for re-shown learning cards show approximate labels and mark them "~". Undo the last offline answer works. Whiteboard, audio, type-in answers, image occlusion, MathJax (bundle MathJax locally so it works offline) and the enabled add-ons' card features keep working where they don't need the server. A small "Offline · 23 answers waiting to sync" banner.
- [ ] Offline study, part 3 (sync back): when the connection returns, send the queue to a new endpoint that replays answers in timestamp order through the real scheduler (answer_card with the recorded time taken and the review time set to when it was answered), skipping a card that was changed or answered elsewhere in the meantime (log it, tell the person "2 answers were skipped because the cards changed on another device"). Exactly-once: each queued answer has a unique id the server remembers, so a retry never double-answers. Then refresh the offline copy. Also queue offline Add card (basic and cloze, text only) and replay it the same way. Tests: replay order, timestamps used, duplicates ignored, conflicts skipped, learning re-shows; a Playwright test that goes offline (context.set_offline(True)), studies 5 cards including an Again, comes back online and checks the revlog on the server.
- [ ] Round 3 regression: run tests/run_all.py and every tests/shots_*.py script (not just shots_all.py), check screenshots of the offline pages at iPad and Chromebook sizes, light and dark, fix anything broken, update README (explain offline: what works, what needs a connection, iPad storage notes) and CHANGELOG.
